# Tests

Node's built-in test runner, no test framework. From the repository root:

    npm test                                                   # everything (about 45 s; builds the P0JBVA rasters first if they are missing)
    npm run fixtures                                           # rebuild the P0JBVA rasters (about 8 s)
    node --test --test-reporter=spec tests/mesh/performance.test.mjs   # timings against the phase 1 budgets

`.github/workflows/test.yaml` runs `npm test` on every push and pull request; `release-on-tag.yaml` runs it again before a release is drafted.

## Layout

- `mesh/`: the v4 mesh engine (`src/mesh/`) and its module integration (`MeshSession`, persistence, the mesh cache, the worker protocol, regional extraction and the exporters), and the edits built on it: the layer tree, deleting, merging and nesting regions, painting with the brush and fill (with the waters that follow), and routes made by hand (placing with a preview, the transports' costs, the waypoints a traced stroke keeps, moving, inserting, removing, splitting, joining, simplifying and re-pathing waypoints), the map's area factor (what a pixel measures in km) and the content transform that carries regions and routes with the terrain when the noise is panned or rescaled, and the noise frame's own undo entry, which steps the terrain back along with everything on it. The integration tests stub the few Foundry globals they reach in `mesh/foundry-stubs.mjs`; the worker test runs the real worker module in a Node worker thread through `support/web-worker-shim.mjs`.
- `ui/`: the studio's interface without a browser: every template compiles with only the helpers both hosts provide (so a template cannot quietly rely on a Foundry-only helper the web version would lack), every statically named partial exists, and every `data-action` in the templates has a handler, and every `--fwmb-*` custom property the stylesheets, templates and scripts read is defined (in both themes); the vector undo history (snapshots, owner patches and composite entries) the Regions panel's commands, each one undo step, the Regions tool's pointer input (picking, painting, its keys, the docked editor), the Routes tool's (drawing routes by click and by stroke, editing them, its keys, the toolbar's fields and the docked route editor), pin quick styles (the default set, the cascade, usage and the toolbar's choice), the long lists' search and filters (`ListQuery`: every matching row listed, how many match while filtered, the rows rendered again only when what they show changes, the row in the inspector and the ticks marked after each draw, the search waiting for typing to pause), Mass Edit's Delete as one undo step, the styles a run can set back to the defaults (`Generation.resetStyles`, and recognising an older default set), the Generate panel (`GeneratePanel`: its settings kept valid, the fields that write them, the estimate, Out of date only after a run, the regional and small-area notices, the last run's results, the Output switches deciding the levels, places, routes and names a run writes, and the Ages section's rows: add, remove, move, each age's era, strife and event, and the estimate per age), and a generator run added to the map (`Generation`: the set, routes, pins and model run as one undo step that undoes and redoes exactly, pin styles found by tier without touching the user's own); the studio's frame (the rail's stages and tools, the width and height classes, the hint's items and inks, and the keyboard shortcuts sheet covering every hint context), and the map controls (both their wide row and the Layers menu read the view state, and every method in `MapStudio` that changes a view updates them); the Labels and Regions menus' rows (`ContentRows`, `content-rows.test.mjs`: the label styles in use and No style, each set with its levels, All, a set's row, what drawing and picking leave out, a tool bringing its rows back, Regions' Fills (borders alone, apart from All), saved with the map; their rows written into both forms of the map controls in `map-controls.test.mjs`); Generate again and Remove generated content (`Regeneration`, `regeneration.test.mjs`: the earlier run replaced in the same Political set as one undo step, an edited county keeping its whole realm, a locked place and an edited route kept with nothing put on a kept place, a set left empty dropped, the stroke, Mass Edit and list-rename paths marking items, undo unmarking them; the shared two-handle track `RangeTrack`'s keys); the map's detail level (`DetailLevel`, `detail-level.test.mjs`: each pin's, route's and Political level's own level, what each level shows, a hidden level left undrawn unless painted, levels drawn as borders alone with Fills off, the starting level for a map's scale, the Detail menu's marks, and the inspectors' Generated rows and a scene export's journal pages for generated items at the shown level); the map's styles in the inspector and Styles and icons (`StyleEditors`, `StyleLists`: each kind opening from its row, a change cascading as one undo step with its style, the add row, Rename, Duplicate, Delete with its count, Save as… undone with its style, a route style's transport narrowing the route pickers, a new map's route and label style seeds); calm ages carry their towns and realm seats on; a plague and war-torn age loses towns and people; a culture arriving is absent before its age and an invading one takes more land; a stop keeps the ages finished; the earlier ages kept in brief in the saved run and checked on import; what the age before leaves (ruins, abandoned castles, old roads, former capitals on their styles, and the Output switch leaving them out) is in `materialise.test.mjs`, their history rows in `detail-level.test.mjs`, and their counts in Results in `generate-panel.test.mjs`. `worker.test.mjs` runs the `generate` task in a Node worker thread: the same result as the main thread, progress, cancelling, the input moved to the worker rather than copied, and a stop asked for (before the run, or part-way through an age) ending it with the ages finished. `p0jbva.test.mjs` runs it on P0JBVA against the settlement prototype's figures on the same map (`fixtures/prototype-baseline.json`): the counts of realms, duchies, counties, settlements by tier and road length within 10% (the module's mesh places its model cells differently from the prototype's, so the comparison is statistical), the time per age against its budget (skipped on CI, like the mesh budgets), and the run written onto the map (realms nesting their duchies and counties, neighbouring realms in different colours, its own time budget). `materialise.test.mjs` writes a run onto the synthetic island (`Materialise`): the political set's three nested levels, titles and territorial waters, routes whose legs join their waypoints cell by cell with their class, transport and style, one pin per place on its tier's style with only capitals' and cities' labels shown, coincident route stretches drawn once by the higher class (`RouteMerge`, and the session's cache of the drawn lines), and the saved model run's codec (`ModelRun`).
- `data/`: input safety (`src/data/Sanitize.js`, `MapRules.js`, `MapImport.js`, `ImageCheck.js`, `MapNames.js`): a complete v4 map and the older samples pass the importer whole; script and markup in every text field stay text (escaped in templates and journal pages); `__proto__`, `constructor` and `prototype` keys are dropped at every depth and pollute nothing (the web host's merge included); unknown keys are dropped; oversized arrays, too many values, deep nesting and huge strings are refused; files that are not maps, or whose sizes, mesh or ids are damaged, are refused; owner arrays are kept only for the map's own layers and the decoder refuses an impossible length; a saved model run passes whole, and one with arrays of the wrong length, bad base64, an impossible cell count or shares that run backwards is dropped; a colour such as `red;background:url(…)` never passes, in a file or in the inspector; enums, numbers, font names and image sources follow their rules; an image is known by its bytes (an SVG renamed `.png` is an SVG); text past its limit refuses an import and is listed by an export; every refusal has a localised message; imported maps keep their names, numbered on a clash. `backup.test.mjs`: the portable map file and the backup (`MapPackage`, `Backup`): images and custom pin icons carried embedded, packaged by hash or not at all (Maps only), brought back the host's way with pins and pin styles moved to the icon added (or matched); unreadable images left out and counted; a backup's round trip with each image once and a map's model run in its file; zips refused for an entry name that climbs out of its folder, a 1000:1 entry (before it is inflated), too many entries, and anything that is not a backup. `symbol-sizes.test.mjs`: pin and label sizes (`SymbolSizes`): a map or styles file saved before the current size unit is scaled once as it is read (an unset size left unset, since its new default is the old one scaled), one saved since is left alone, and a legacy pixel label width still becomes the same number of characters. `svg-clean.test.mjs` cleans SVGs in headless Chromium (DOMPurify needs a real browser's parser) and is skipped, saying so, where no Chromium is found (set `FWMB_CHROMIUM`).
- `canvas/`: the 3D view's lighting normals (`LightingNormals`): flat ground lit straight up, the fine slope alone at no emphasis, the broad slope growing with the emphasis under its soft cap, land and sea bed blurred apart at a coast, flat water lit flat, and finite normals at the edges. Placing names so they do not cover each other (`LabelPlacement`: free places first, the important labels first, fixed boxes kept clear, soft icons covered only when nothing better is free, a name that must show pushing out lighter ones, annealing fitting more than greedy alone, the same placement for the same seed, a change moving only the labels near it, and thousands of names in well under a second) and where each name goes (`LabelLayout`: a pin's name round its pin, a capital's before a realm's, a label with its own position kept, a region's name inside its region where it can be, and every name at its first place with Avoid overlaps off); a region's places for its name (`BorderArcs.labelCandidates`, in `mesh/border-arcs.test.mjs`).
- `platform/`: the host services (`src/platform`), including Foundry's image storage for imports (`foundry-assets.test.mjs`: one upload per image into the world's `fwmb-assets` folder, named by hash; a failed upload is an error). Foundry's pass calls on to Foundry as the module always has; the web version's behave as Foundry's do where the shared code relies on it (saved maps, settings, strings, templates, asset paths, the file picker).
- `support/`: shared helpers that are not tests. `pipeline-setup.mjs` builds a stand-in for the studio app from a saved map so the generation pipeline can run outside Foundry; `web-worker-shim.mjs` gives Node a browser-style module `Worker`.

Two checks run the studio in headless Chromium (Playwright) and stay in `design/`, run by hand: `design/prototypes/thin-frame/studio-smoke-check.mjs` (the studio in a stand-in Foundry window) and `design/prototypes/web/web-smoke-check.mjs` (the web version, from the working copy or any site address). The browser render check for the region fill (`design/tests/mesh/browser/render-check.mjs`, headless Chromium through Playwright) stays in `design/` and is run by hand; it reads the fixtures from here.

## Fixtures (`mesh/fixtures/`)

- `p0jbva.json`: the P0JBVA map (2000 × 1600, seed `P0JBVA`), the saved-map JSON the other fixtures are built from.
- `p0jbva/`: the map's terrain rasters (elevation, water mask, river map, moisture and temperature) and its traced rivers with their flow, **derived data that is not committed**: `build-p0jbva.mjs` regenerates them by running the module's own generation pipeline on `p0jbva.json`, so they always match the current engine. `npm test` builds them when they are missing; `npm run fixtures` rebuilds them after an engine change. Tests that need them skip, and say so, when they are absent.
- `v3-vectors.json`: `p0jbva.json` with hand-written v3 region layers (an overlapping pair, one around a lake, a tiny one), routes (two sharing a node, one repeating a node) and pins, for the migration tests.
- `p0jbva-realms.json`: the settlement prototype's final realms carried onto P0JBVA's display mesh (vote, fill, relax, sea claims), RLE encoded, with the mesh block they belong to. Rebuilt with `make-realm-layer.mjs` from a prototype run; only needed again if `MESH.ALGORITHM_VERSION` changes.
- `expected-sites.json`: hashes of the sampled sites, the cross-engine determinism check. If it fails after a deliberate sampler change, bump `MESH.ALGORITHM_VERSION`, regenerate this file and the realm fixture.

## Conventions

- Files are `*.test.mjs`; anything else under `tests/` is a helper or fixture and is not run.
- Tests must pass on a shared CI runner: the performance budgets are skipped where `CI` is set (set `FWMB_PERF` as well to run them there).
- A harness in `design/` that becomes a repeatable check moves here; a one-off investigation stays in `design/`.
